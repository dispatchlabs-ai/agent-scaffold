# Draft release notes

1. Read company/company-writing-style.
2. Read references/template.md with read_skill using this skill's ID.
3. Separate new capabilities, fixes and actions the user must take.
4. Draft from the supplied changes. Leave out commit hashes and internal jargon
   unless they explain something the reader needs to do.
5. If a section has no supplied facts, say “None reported.” Do not invent work.

Return the draft in chat. Publication requires a separate integration and request.
